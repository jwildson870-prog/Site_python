# Portal Python — visual brief

## Regra principal

Refinements must preserve the incumbent visual identity and existing color palette unless the user explicitly requests a redesign.

## Surface

- Platform: adaptive web application.
- Primary surfaces: student portal, professor dashboard, materials, activities, reports, forms and presentation viewer.
- Mode: Operate. Scanability, consistency, accessibility and task completion take priority over decoration.

## Incumbent visual language

- Dark academic/technical interface.
- Existing blue/cyan/teal palette is locked for refinement work.
- Existing sidebar, cards, dashboard structure and content hierarchy are preserved.
- Rounded controls and compact panels are part of the current identity; refine consistency rather than replacing them.

## Refinement rules

- Do not replace or retheme the palette during polish work.
- Prefer existing tokens and components over one-off styles.
- Keep hover feedback subtle and reserve movement for useful feedback.
- Use strong ease-out curves for UI responses and keep UI motion short.
- Respect `prefers-reduced-motion`.
- Keep keyboard focus visible.
- Avoid horizontal overflow at mobile/tablet/desktop widths.
- Keep touch targets comfortable on coarse pointers.
- Long labels and user content must wrap instead of breaking layout.
- Preserve routes, forms, database behavior, authentication and storage behavior during visual-only passes.
